信号处理函数

发表于 2026-06-17 更新于 2026-07-20 分类于 面试
本文字数： 1.4k 阅读时长 ≈ 2 分钟

信号处理函数（Signal Handler）是操作系统（尤其是 Unix/Linux 系统）编程中的一个核心概念。简单来说，它是程序员自定义的一个回调函数，用于告诉进程在接收到特定的“信号”时应该执行什么操作。

以下是关于信号处理函数的详细解析：

1. 什么是信号？

在理解处理函数之前，需要先理解“信号”。信号是操作系统向进程发送的一种异步通知机制（本质是软中断），用于告知进程发生了某个事件。常见信号包括：

  • SIGINT (2): 用户按下 Ctrl+C，请求中断程序。
  • SIGTERM (15): 请求终止进程（如使用 kill 命令）。
  • SIGSEGV (11): 段错误，非法内存访问。
  • SIGALRM (14): 定时器超时。

2. 信号处理函数的作用

默认情况下，操作系统对每个信号都有预设行为（如终止、忽略或暂停）。通过注册信号处理函数，你可以覆盖这些默认行为，实现自定义逻辑，例如：

  • 优雅退出：捕获 SIGINT 或 SIGTERM，在退出前保存数据、关闭文件或释放资源。
  • 重载配置：Nginx 等服务器捕获 SIGHUP 来重新加载配置文件而不重启。
  • 清理子进程：捕获 SIGCHLD 来自动回收僵尸进程。
  • 调试与监控：捕获异常信号进行日志记录或转储。

3. 如何注册信号处理函数

在 C/C++ 中，主要有两种方式注册：

(1) signal() 函数（简单但较旧）

(2) sigaction() 函数（推荐，更安全可控）

sigaction 提供了更精细的控制，如指定信号掩码、标志位等，避免了 signal() 在不同系统上的行为差异和竞态条件问题。

4. ⚠️ 关键注意事项与陷阱

编写信号处理函数时必须极其谨慎，因为它是在异步上下文中执行的：

  • 可重入性与安全性：信号可能在程序执行任何位置时打断主流程。因此，处理函数内部只能调用异步信号安全（Async-Signal-Safe）的函数（如 write, _exit, signal 等）。严禁调用 printf, malloc, new, std::cout 等非安全函数，否则可能导致死锁或数据损坏。
  • 最佳实践——标志位模式：最安全的做法是在处理函数中仅设置一个全局标志位（如 volatile sig_atomic_t flag = 1;），然后在主循环中检查该标志位并执行实际的复杂逻辑。
  • 多线程限制：在 Python 等语言中，信号处理函数只能在主线程中注册和触发；在 C/C++ 多线程程序中，信号通常只会被传递给其中一个线程，需特别注意同步问题。
  • 不可捕获的信号：SIGKILL (9) 和 SIGSTOP (19) 由内核直接处理，无法被捕获或忽略。

5. 跨语言支持

除了 C/C++，许多高级语言也封装了信号处理机制：

  • Python: 使用 signal.signal(signal.SIGINT, handler) 注册，但受 GIL 和主线程限制。
  • Go: 使用 os/signal 包，通过 channel 接收信号，更符合 Go 的并发模型。
  • Rust: 使用 signal-hook 等 crate，强调内存安全。

总结来说，信号处理函数是程序与操作系统底层事件交互的桥梁，它赋予了程序应对突发状况的能力，但也要求开发者对并发安全和系统底层机制有深刻的理解。
